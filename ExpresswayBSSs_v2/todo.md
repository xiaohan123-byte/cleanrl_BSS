# MPC-RL 后续工作清单

## P0：解决调整成本为0的问题
调整算例。增大规模。减小成本系数。放宽基准路径生成的方式。

## P0：增加预约不可行惩罚（已完成）
- [x] 按预约换电事件增加可配置违约成本；预约缺供时先用尽物理满电库存，随机用户不得越级。
- [x] 区分预测风险与实际违约；只有实际首期违约进入全天结算，并使该用户后续事件失活。

## P0：建立统一、可复现的实验协议

- [ ] 所有算法使用完全相同的候选网络、预约样本、预测随机需求和实际随机到达；同一随机种子下采用配对比较，禁止不同算法各自重新抽样。
- [ ] 把关键实验参数全部配置化：`H`、`beta`、路径调整惩罚、充电策略、随机种子、求解时限、终端库存处理和是否允许策略性限流。
- [ ] 每次运行保存完整元数据：代码提交哈希、schema版本、参数快照、输入文件哈希、Gurobi版本、求解状态、MIP gap、best bound、运行时间和异常信息。
- [ ] 统一结果定义：
  - 全天绩效使用实际首阶段结算之和，不能累加重叠窗口的 `objective.total`；
  - 所有方法使用相同的终端库存价值或相同的终端库存约束；
  - 明确是否计入电池折旧、固定运营成本和拒单惩罚。
- [ ] 验收标准：给定同一配置和种子可重复生成相同的业务决策与汇总指标；求解时间等非确定性诊断字段可存在小幅差异。

## P1：开展多随机种子稳健性实验

- [ ] 先使用不少于30个随机种子进行正式评估；训练种子、验证种子和测试种子分开管理。
- [ ] 对每个种子保存站点—时段级需求、服务、拒绝、充电功率、SOC轨迹、预约路径和实际结算。
- [ ] 对核心指标报告均值、标准差、中位数、四分位数和95%置信区间，并报告最差种子，而不是只展示 seed=42。
- [ ] 使用配对差值比较算法，例如对每个种子计算“PPO-MPC净收益减去规则基线净收益”，再汇总差值的置信区间。
- [ ] 验收标准：结论不能依赖单个种子；主要算法相对基线的收益、服务率和求解时间差异具有稳定方向。

## P1：构建消融实验与可解释基线

- [ ] `H=1`：只做单步滚动优化，用于衡量多步前瞻 `H=4` 的价值。
- [ ] `beta=0`：移除终端 critic 价值，用于衡量终端价值对充电、拒单和日末库存的影响。
- [ ] 静态日前方案：运行过程中不调整预约路径，并按日前库存/需求计划执行，作为“无在线重优化”基线。
- [ ] 规则充电基线：使用明确的低SOC优先、阈值充电、低谷充电或“缺口补足”规则，不使用训练后的 actor/critic。
- [ ] 建议补充组合消融：`H=1,beta=0`、`H=4,beta=0`、`H=4+Mock critic`，从而分别识别滚动前瞻和终端价值的贡献。
- [ ] 所有基线必须使用与主方法相同的预约优先、随机 FCFS、功率上限、SOC转移、价格和实际需求样本。
- [ ] 验收标准：形成一张可以独立解释各模块增益的消融表，而不是只比较最终 PPO-MPC 与一个弱基线。

## P1：建立完美信息全日 MILP 上界

- [ ] 构建一次性全日模型，预先知道全部实际预约入口信息和实际随机到达，用与在线模型一致的物理约束和成本口径求解。
- [ ] 明确该模型是“非因果性能上界”，不能作为可部署策略，但可用于衡量预测误差和滚动决策造成的最优性损失。
- [ ] 对每个测试种子计算最优性差距：`(upper_bound - online_reward) / |upper_bound|`，同时比较服务率、充电成本、路径调整和最终库存。
- [ ] 如果全日MILP在大实例上不能证明最优，保存 incumbent、best bound 和 MIP gap，并把上界口径写清楚。
- [ ] 验收标准：能够回答“当前在线策略距离完美信息最优还差多少”，并区分差距来自预测误差、有限时域还是RL策略。

## P2：接入并评估训练后的 PPO-MPC

- [ ] 用真实 PPO actor 替换 `MockRLProvider` 的请求功率，确保动作经过槽位功率、站级功率和SOC可行域投影。
- [ ] 用训练后的 critic 提供终端SOC价值和域外预约事件价值；记录价值尺度，避免终端项压倒实际收入与成本。
- [ ] 训练过程保存 checkpoint、配置、随机种子、TensorBoard曲线、验证集最佳模型和早停依据。
- [ ] 训练期间和最终测试严格分离；最终表格只使用从未参与调参的测试种子。
- [ ] 与规则充电、`H=1`、`beta=0`、静态日前和完美信息上界在相同测试样本上比较。
- [ ] 验收标准：PPO-MPC不仅提高模型目标，还应在实际结算净收益、随机服务率或购电成本中体现稳定改进，且不能降低预约履约率。

## P2：统一评估指标与结果展示

- [ ] 业务指标：实际净收益、预约履约率、随机服务率、拒绝数、路径调整率、预约/随机收入、充电成本和模型未计入成本说明。
- [ ] 运行指标：每轮与全天充电量、峰值功率、分时电量、各站最终SOC、物理满电数、开放服务数及站点间库存不均衡程度。
- [ ] 预测指标：按站点—时段计算需求数量与SOC预测的 MAE/RMSE，并分析预测误差与拒单、收益损失之间的关系。
- [ ] 求解指标：状态分布、平均/最大/P95求解时间、MIP gap、best bound、超时率和不可行率。
- [ ] 至少输出以下图表：逐期实际收益分解、服务/拒绝量、站点功率与电价、SOC库存轨迹、算法箱线图、相对完美信息上界的差距。
- [ ] 验收标准：实验结果可以从“收益、服务质量、库存、预测误差、计算效率”五个维度复核，不依赖单个汇总数字。

2. 固化实验协议、配置和结果schema。
3. 实现 `H=1`、`beta=0`、静态日前和规则充电基线。
4. 实现完美信息全日MILP上界。
5. 执行多随机种子基线与消融实验。
6. 训练并接入PPO actor/critic。
7. 在独立测试种子上完成同场比较、统计检验和图表汇总。
