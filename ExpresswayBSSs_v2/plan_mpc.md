# 论文 MPC-RL 中 MPC 部分实现计划

## 摘要

- 全新实现当前 `paper/mian11_fixed.tex` 的逐电池槽位 MPC，不恢复旧版聚合库存模型。
- 仅新增用户指定的六个 Python 文件；原有 base 项目和论文文件保持不动。
- 使用标准库与现有 Gurobi 12.0.1；真实用户环境下的 Gurobi 许可证已验证可求解。
- 采用已确认的一致性修正：`H` 表示总控制步数，控制期为 `ell ... ell+H-1`、终端状态为 `ell+H`；候选网补入口直达出口弧，并按用户精确 SOC 在线过滤。
- 默认输出到 `data_generation_test/output/`：`candidate_network.json`、`mock_rl_data.json`、`dayahead_plan.json`、`mpc_run_result.json`。

## 实现内容

### 1. 业务参数与模拟数据

在 `data_generation_test/parameter.py` 中：

- 定义 `StationParameters`、`ODPairParameters`、`SolverParameters`、`BusinessParameters` dataclass，以及 `get_default_parameters()`、`validate()`。
- 集中保存时段、预测长度、站点与槽位、初始逐槽 SOC、位置、车速、续航、SOC 分档、出口最低 SOC、电池容量、效率、槽位/站级功率上限、电价、换电服务价、路径调整惩罚、预约换电违约成本、终端价值权重和 Gurobi 参数。
- 默认构造可快速求解的非平凡实例：8 个一小时时段、`H=4`、3 站×5 槽、100 kWh 电池、300 km 续航、2 个 O-D；站点位于 80/180/280 km，目的地位于 230/380 km；SOC 档为 `[0.30,0.50)`、`[0.50,0.75)`、`[0.75,1.00]`。
- 默认充电效率 0.95、60 kW/槽、240 kW/站，分时电价为 `[0.35,0.35,0.65,1.10,1.10,0.65,0.40,0.35]`，固定种子 42，Gurobi 单线程、30 秒时限。

在 `data_generation_test/rl_data.py` 中：

- 生成四名预约用户、日前信息、实际入口时刻/SOC 偏差、逐请求随机需求预测、实际随机到达及初始逐槽 SOC；至少包含一次随机需求超过剩余电池数的场景以验证 FCFS。
- 提供 `generate_mock_data()`、`save/load_mock_data()`。
- 定义可替换的 `RLProvider` 协议和 `RLSignals`：逐槽请求功率、终端 SOC 边际价值、域外换电价值。
- `MockRLProvider` 使用受槽位及站级功率限制的确定性充电策略；模拟线性 critic，令终端梯度为正、域外价值按 `lambda_i*(rho-1)` 计算，确保终端接口真正进入目标而非全零占位。

### 2. 候选网络与日前计划

在 `data_generation_test/candidate_network.py` 中：

- 提供 `generate_candidate_network()`、`get_feasible_arcs(entry_soc)`、`validate_candidate_network()`、`save/load_candidate_network()` 和 CLI。
- 按论文四步实现：生成下游原始弧、标准库 DFS 枚举完整路径、按距离顺序剪除可替代的过近弧、合并保留路径形成分档网络。
- 增加三项一致性约束：
  - SOC 足够时生成入口到出口直达弧；
  - 离线分档网络作为超集，使用时按精确入口 SOC 过滤，并清理无法组成完整路径的弧；
  - 任一节点能够满足出口最低 SOC 时，仅保留直达出口的出弧，防止为增加收益而进行不必要换电。
- 剪枝时同时保证 SOC 档下界用户仍保有完整路径；所有并列按节点位置、节点 ID 固定排序。
- JSON 保存 schema 版本、节点与位置、距离、SOC 消耗、SOC 档、候选弧和完整路径。

在 `src/dayahead_plan.py` 中：

- 文件开头写详细中文说明、调用示例、输入输出格式及未来真实 actor 接入方式。
- 提供 `generate_dayahead_plan()`、`save/load_dayahead_plan()` 和 CLI。
- 按提交顺序处理预约，并对每个请求事务式试排：
  - 使用日前 SOC 的精确可行网络；
  - 每期依次充电、预约优先服务、随机 FCFS 服务；
  - 退回电池从下一期才可充电；
  - 能直达出口即结束，否则只考虑有满电预约余量且存在下游完整路径的站点；
  - 按“预约后、随机前的满电余量降序—更靠近出口—站点 ID”选择；
  - 中途失败时完整回滚该用户的所有临时预留。
- 输出接受/拒绝结果、拒绝原因、日前节点路径及弧、预计换电时段、退回 SOC、基准站点访问量和预测库存轨迹。

### 3. MPC 主体与滚动执行

在 `src/mpc_model.py` 中：

- 文件开头写详细中文说明，包含时域索引、论文公式映射、数据文件接口、RL 接口和最小调用示例。
- 公开 `ReservationObservation`、`RandomRequest`、`FixedCommitment`、`RollingState`、`RLSignals`、`MPCWindowInput`、`MPCResult` 等 dataclass。
- 提供 `MPCController.from_files(...)`、`build_model()`、`solve_step()`、`execute_period()`；显式接收参数对象、候选网络文件、日前计划文件和 `RLProvider`。
- 用 Gurobi 完整实现：
  - 预约路径二元变量及入口—出口流平衡；
  - 相对日前站点序列的路径调整指示；
  - RL 请求功率截断、连续充电转移和服务就绪变量；
  - 可调整预约、固定承诺、预测随机三类事件；
  - 预约优先、预约缺供显式违约变量和随机请求严格 FCFS 前缀；预约缺供时全部物理满电池先给预约，随机余量为零；
  - 事件—槽位匹配、最小可用槽位和无交叉规范化约束；
  - 换电后逐槽 SOC 转移；
  - 预约/随机服务收益、实际充电成本、一次性调整成本、预约换电违约成本、终端 SOC 梯度和域外事件价值。
- 事件顺序固定为：预约按“已发布固定承诺、本轮新到、尚未发布未来预约”分级，再按到站时刻、用户 ID、入弧排序；随后按到站时刻和请求 ID 排序随机事件；槽位始终升序。
- 用统一的 `epsilon_soc` 将 `g` 与充电后物理满电状态双向绑定；容差带内自动补足到 SOC 1，满电池不能被经济目标主动关闭，且不再设置关于 `g` 的次级目标。
- 不设置旧模型的终端满电库存下界。
- 预约事件维护有效到达—站内履约—违约链；上游违约后，同周期执行事件、预测域内下游事件及域外价值均失活，避免重复服务、重复计罚或继续估值；固定承诺域内失败时同步撤销参考轨迹中的域外事件价值。预测违约仅作为窗口风险，实际首期违约才结算并取消用户后续事件。
- 返回目标分项、全部预测路径、仅本轮新到用户的待发布路径、`P/g/F/S/z/alpha/d`、预约风险、首阶段执行包和终端状态；预约违约松弛后仍无 incumbent或输入不合法时给出明确异常及 IIS 约束名称。

在根目录 `run_mpc.py` 中：

- 用 `argparse` 提供 `--seed`、`--regenerate`、输入/输出路径、求解时限和求解日志开关。
- 默认依次生成候选网络、模拟数据和日前计划，然后逐时段滚动：
  1. 将预约划分为未进入、本轮新进入、已发布在途、已完成和实际违约五种互斥状态；
  2. 逾期未到用户保留在未进入状态，并把有效 ETA 更新到当前窗口，避免从模型集合消失；
  3. 获取本轮随机预测和 RL 信号并求解完整 `H` 步模型；
  4. 只发布本轮新进入预约的路径，未来预约路径全部丢弃；
  5. 只执行第一期充电和服务；
  6. 用实际预约事件与实际随机到达更新物理 SOC，预测随机请求绝不写入真实状态；
  7. 新发布且尚未完成的路径转为固定承诺。
- 输出逐轮目标、发布路径、预测风险、实际预约违约、功率、SOC、固定承诺和最终汇总，并在每轮检查 SOC 范围、电池数守恒、物理满电与 `g/F` 一致及状态首尾衔接。

## 测试与验收

- 运行 `py_compile` 检查六个文件，并分别运行候选网络、模拟数据和日前计划 CLI。
- 验证候选弧全部向下游、完整路径首尾正确、精确 SOC 可达、直达出口优先、剪枝后每个有效 SOC 档仍有路径。
- 验证日前库存无负值、拒绝请求无残留预留、当期退回电池不能当期充电。
- 构造请求不足、容差内补足、超过补满和初始满电四种充电情况，核对两个闭合功率分支、SOC 和购电成本。
- 验证路径流平衡、`d` 的变更识别、预约优先、预约缺供软化、上游失败后的有效链、随机 FCFS、最小槽位匹配、固定承诺不可调整以及非零 critic 项进入目标。
- 以真实用户权限运行 `python run_mpc.py --seed 42 --regenerate`；要求每轮获得最优解、滚动状态连续、只执行首阶段、最终 JSON 可重新加载。
- 同一 seed 重跑，候选网络、模拟数据、日前计划、路径决策和目标值一致；运行时间等非确定性诊断字段不参与比较。

## 明确假设

- 使用当前 Gurobi，不增加 pandas、numpy、networkx、tyro 或其他求解器依赖。
- 连续时刻统一归入半开区间 `[q,q+1)`。
- 模拟 actor 与线性 critic 只用于打通接口；未来真实 RL 负责计算请求功率、参考终端梯度和域外事件价值，MPC API 无需修改。
- 域外收益按论文原目标处理：只加入 critic 域外换电价值，不额外创造新的服务收益项。
- 站内库存不足时按预约换电事件计违约成本；预测域仅报告风险，实际首期违约进入补偿状态并取消该用户后续事件。设备故障等其他应急优化仍不在本文范围内。
- 不兼容的旧 `src/random_test.py`、`src/parameter.py` 及其他 base 文件不修改；新规范入口仅为 `run_mpc.py`。
