# 时序假设说明

## 预约用户的观测时刻与滚动决策时刻

`ell` 表示滚动决策发生的离散时刻，而不是预约用户物理进入高速公路的
时段。系统在 `ell` 时刻只能观测到
`((ell-1) * Delta, ell * Delta]` 内已经进入高速公路的预约用户，不能知道
`ell` 之后才会出现的实际到达信息。因此，这些用户在 `ell` 时刻首次进入
滚动 MPC、使用实际入口时刻和实际入口 SOC 求解并发布路径，符合因果性，
不属于“晚一个时段进入 MPC”。`[ell, ell+1)` 内才进入的真实用户必须等到
下一个决策时刻才能使用其实际信息。

## 当前采用的明确物理假设

当前原型要求：

> 决策周期必须短于用户从入口到第一个可能换电站的最短行驶时间。

记决策周期为 `Delta`，入口到各 O-D 第一个可能换电站的最短行驶时间为
`tau_first_min`，必须满足：

```text
Delta < tau_first_min
```

在该假设下，对任意在 `((ell-1) * Delta, ell * Delta]` 内进入的预约用户，
系统在 `ell` 时刻发布路径时，用户尚未到达第一个可能换电站，因而能够从
`ell` 开始执行新发布的换电路径，不会出现路径尚未发布、用户已经到站的
物理矛盾。

当前模拟数据的 `Delta = 1 h`。默认首站距入口 80 km，模拟车速为
75 km/h，因此：

```text
tau_first_min = 80 / 75 = 1.0667 h > 1 h = Delta
```

`generate_mock_data()` 会主动检查入口到第一个可能换电站的最短行驶时间
必须严格大于 1 小时；不满足时直接报错，不生成不符合当前时序假设的模拟
数据。
