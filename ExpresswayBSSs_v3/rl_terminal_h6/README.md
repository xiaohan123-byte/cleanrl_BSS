此目录实现论文第 5.1 节的 β=1、H=6（90 分钟）设置，基础随机种子为 1。独立复制已完成零终端实验的最终引擎，来源和原始 SHA256 见 `baseline.json`。共享 `src/`、原 CSV、零终端结果和论文正文均未修改。

2026-09-19 根据用户确认，正式预约失败惩罚改为 **200元/人**，从第一批重新采样策略轨迹和训练。业务覆盖参数保存在 `plan.json` 的 `business_overrides`，同时作用于优化参数、实际场景执行与训练回报。原70天场景文件仍保持原始哈希；每个任务另外记录应用覆盖参数后的场景哈希。原1000元轨迹和模型不能复用。旧零终端实验仅用于继承引擎和检查进程冲突，不作为200元设置下的性能对照；正式比较需要同为200元的零终端结果。

## 固定数据与实验队列

数据为 `data/final_real_data_v1` 中的“基于真实均值的泊松合成场景”，沿用全部 11 站、250 块电池、6 出入口、26 O–D、200 预约和200随机请求，以及相同误差、初始满电库存和日前路径。每个日任务校验场景哈希和日前路径。

- 测试：按周一至周日为 `[1,37,3,4,19,13,14]`，与零终端实验相同。
- 验证：`[57,65,31,67,47,34,42]`，由 `SeedSequence([1,320])` 抽取。
- 训练：剩余56天，以 `SeedSequence([1,321])` 按星期分为4批，每批14天、每种星期2天；完整清单写入输出 `plan.json`。
- 第一批使用零终端策略；后续批次使用上一批拟合模型。每批拟合后在固定7个验证日运行；按验证平均实际净收益选模型，同分选较早批次。选定模型在7测试日各运行一次。
- 总共56训练日任务、28验证日任务、7测试日任务，即91个日任务和4次网络拟合。不重复运行已完成的零终端测试日，不进行多种子重复。

## 与论文第4节的对应关系

`state_encoding.py` 仅接受当前可观测状态。电池采用共享仿射/ReLU映射后按站求和；预约先编码请求、按用户求和、映射用户并减去空用户映射，再对用户求和；随机请求单独编码求和。尚未明确时间的后续预约填零并使用时间掩码；等待预约只编码一次。域外随机需求由历史均值预测进入外部输入，不读取未来真实请求。

编码器维度分别为4（电池）、8（预约请求）、8（用户）、4（随机请求）。外部输入包含绝对时刻、剩余需求期、路径更新相位、当前价格、之后24个小时窗口的价格和需求预测。11站状态编码维度为874，价值头为仿射直连加16个ReLU，含编码器共15,395个可训练参数。额外的吸收态开关不属于可训练输入维度：24小时后仍有待服务请求时保留价值，处理完后价值严格为零，不计库存残值。

所有编码器和价值头共同更新。训练保存原始结构化状态，使用实际净收益的未折扣完整回报，包括跨日处理，末状态目标为0。连续输入归一化仅由第一训练批次拟合后冻结；二值输入和掩码保持原值。每批 Adam，学习率0.001、无权重衰减、批量256、200轮；后续批次继承权重、重置优化器，使用当前批次样本。回报除以1000用于回归，嵌入MILP时恢复为元。网络初始化使用seed=1，洗牌使用 `SeedSequence([1,330,iteration])`。CUDA启用确定性计算、关闭TF32。

`learned_value.py` 将固定网络精确嵌入 COPT。连续 SOC 的ReLU采用物理边界；用户终端状态按所选路径和前站服务时刻枚举，保留后站服务依赖、车辆位置/SOC和路径记录。边界到达、截止时刻恰好可服务和跨日处理保持与执行器一致。每轮独立检查导出网络与MILP计算、特征界限和状态编码的一致性。

业务约束沿用冻结引擎。时间段和充电更新15分钟、路径更新30分钟、最长等待30分钟、调整费10元；求解120秒、相对gap 0.0001、最多16线程，日任务串行。存在时限可行解时继续并记录真实gap，没有可行解时保存诊断并停止。没有全局截止时间。收入、充电、路径调整和失败费用按实际执行记账；预约失败仅罚一次，未发布计划变化不计实际调整费。

论文第4节算法表仍有5/15分钟的默认文字；本实验明确使用第5节覆盖后的15/30分钟。跨日结算、输入尺寸及训练超参数属于本次实验具体设置。此目录不擅自改动共享论文，正式结果的统计和LaTeX更新片段待用户后续询问时生成。

## 运行与恢复

使用 `D:\App\miniconda3\envs\py310\python.exe`。当前正式输出目录为 `outputs/rl_terminal_h6_seed1_failure200_v1`。先运行 `preflight.py --dataset ... --output .../preflight --failure-penalty 200`；验收包括真实数据、业务约束、非等量槽数、午夜结算、断点恢复、GPU联合训练、独立执行与终端编码对照、惩罚更改后的单次实际扣费及回报，以及一个训练日43的单窗口诊断。诊断网络未训练且丢弃，不进入正式模型或测试结果。

随后运行 `run.py --dataset ... --output ... --baseline ... --prepare-only --failure-penalty 200`，冻结源码、数据清单、划分和配置。正式命令必须使用输出目录 `prepared.json` 中的源码快照下的 `run.py`，使用相同三个路径参数及 `--failure-penalty 200`。输出目录与每个子任务均使用操作系统互斥锁。

中断后可对同一冻结入口加 `--resume`：已完成且哈希一致的任务跳过，日内轨迹从最后提交时段恢复；源码、场景、策略或输入身份变化均拒绝复用。失败不会自动改模型、回退零价值或替换日期。

`status.json` 保存控制器当前任务；各日目录保存日志、逐轮journal、原始状态、求解状态/gap/耗时、服务事件、库存、账务、压缩完整结果和核验指标。`fit/` 保存模型、归一化、训练样本来源、各层梯度/参数变化和拟合记录。`selection.json` 只依据验证数据选模型，`selected_model.json` 在测试前冻结。主表求解时间应采用 `solver_demand_seconds_mean/p95`（每天需求期96轮），`solver_seconds_mean/p95` 为包含跨日的补充统计；均再对7天等权平均。

正式进程启动后，本会话按用户要求停止监控。控制器自行执行既定队列；完成后仅保存原始输出和完成状态，不自动生成测试汇总或修改论文。待用户主动询问时再统计结果。
